\subsection{Overall Analyses}\label{subsec:overall}

\subsubsection{Execution and Online Adaptation}\label{subsec:execute}
The hybrid search returns a pushing schedule
$\pi = \{\tau_1,\cdots,\tau_K\}$, with
$\tau_k \triangleq (\Omega_{m_k},\mathbf{v}_k,\boldsymbol{\xi}_k)$.
The schedule is executed in a receding-horizon manner: for each $\tau_k$ the
robots reach the mode~$\boldsymbol{\xi}_k$ and follow the pushing
direction~$\mathbf{v}_k$ from the current state, as in~\eqref{eq:sim}.
\change{On the hardware the optimized forces certify feasibility rather than being
commanded: a mode is kept only if its wrench lies within the actuation limits, and each control interval $\mathsf{EvalSim}$ predicts a short object-motion reference tracked with motion-capture feedback, so every executed push updates the execution state and the WCCG for the next task.} During transitions, robots are
reassigned by preserving the contact-point order along the obstacle
boundary~\cite{tang2026pushingbots}, reducing path crossings. After each push the state is updated, the WCCG is rebuilt, and execution continues
until a $W$-clear path
$\mathcal{P}^W_\texttt{V}$ connects~$\mathbf{x}_\texttt{V}^{\texttt{S}}$ and
$\mathbf{x}_\texttt{V}^{\texttt{G}}$.
Replanning is triggered by observed execution discrepancies -- failed contacts,
stalled pushing, or invalidated WCCG connectivity; Alg.~\ref{alg:pihs}
is then re-invoked.

\subsubsection{Computational Complexity}\label{subsubsec:complexity}

Given~$M$ movable obstacles, the computational cost of one node
expansion in Alg.~\ref{alg:pihs} is dominated by candidate generation and
physics validation. The WCCG update and gap ranking incur
$\mathcal{O}(M\log M+|\mathcal{V}|+|\mathcal{E}_c|+|\mathcal{E}_b|)$ and
$\mathcal{O}(|\Gamma_{\mathcal{L}_\nu}|
\log|\Gamma_{\mathcal{L}_\nu}|)$ costs.
\change{The dominant cost is physics validation, which grows with the number of
evaluated candidates; parallel workers reduce the rollout wall time.} 
\change{Robot-team size affects mode generation: each greedy sweep evaluates at most $N|\mathcal{A}|$ single-contact
substitutions, where $|\mathcal{A}|$ bounds the reachable contact candidates considered per
robot, rather than $|\mathcal{A}|^N$ joint tuples, and refinement is capped by a fixed evaluation
budget; failures are handled by bounded backtracking with budget $B$ and a reduced-team fallback over
at most $N$ one-robot-excluded subsets. Each candidate is checked by an LP over at most $2N$ force variables.}
